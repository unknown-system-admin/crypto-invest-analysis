# 高頻槓桿交易機器人設計（OKX demo）

日期：2026-09-06

## 目標

建立一個本地執行的日內高頻交易機器人：
- 使用者啟動時運行、關閉時停止（無固定時段，約每天 8 小時）
- 自動追蹤混合式訊號（高 TF 定方向 + 低 TF 抓進出）
- 使用 5x 槓桿，逐倉模式
- 先跑 OKX demo 盤（paper trading），不碰真錢

## 需求決策（使用者確認）

| 項目 | 決定 |
|------|------|
| 資金模式 | OKX demo 盤（先 paper，驗證後才考慮真錢） |
| 訊號設計 | 混合式：1h 動能定方向 + 5m/15m 動能 delta 抓進出 |
| 執行位置 | 本地電腦（避開 Render env var 問題，使用者人在旁） |
| 槓桿 | 5x |
| 資產 | BTC/USDT + SOL/USDT |
| 運作方式 | 啟動就跑、關掉就停，無固定時段 |
| 單日虧損上限 | -10% session 起始權益，觸發後強制平倉並停止當日交易 |
| 單筆停損 | -2.5%（市價單） |

## 架構

獨立的 `bot/` 目錄，與現有 FastAPI/monitor 完全隔離。

```
bot/
├── config.py      # 參數：槓桿5x、時間框架、風險上限、資產
├── signals.py     # 混合訊號（HTF方向 + LTF進出場）
├── risk.py        # 風險引擎（單日-10%、單筆-2.5%停損、倉位計算）
├── executor.py    # OKX demo 執行（ccxt sandbox、槓桿、訂單）
├── state.py       # 狀態持久化（實際倉位、損益、session資訊）
├── loop.py        # 主迴圈
└── run_bot.py     # CLI 啟動入口
```

### 模組職責

- **config.py**：所有可調參數集中定義（槓桿、時間框架、閾值、風險上限、資產列表）。不含密鑰，密鑰從環境變數讀。
- **signals.py**：純函數，輸入 K 線資料，輸出訊號（做多/做空/無動作）。可獨立單元測試。
- **risk.py**：純函數，輸入目前狀態 + 市場資料，輸出允許動作與倉位大小。含單日虧損檢查、停損檢查、倉位大小計算。
- **executor.py**：所有 OKX 互動（查詢餘額/倉位、設槓桿、下單、平倉）。唯一有 side-effect 的層。
- **state.py**：session 狀態的讀寫（JSON 檔案），含崩潰恢復的對帳邏輯。
- **loop.py**：主迴圈，串起以上模組。
- **run_bot.py**：entry point，處理 Ctrl+C 與啟動參數。

## 訊號邏輯（混合式）

### HTF 方向閘門（1h 動能分數）

動能分數沿用 `feature_engine/momentum.py`（權重 RSI 0.3 / MACD 0.1 / SMA20 0.4 / SMA50 0.2，範圍 -1~1）。

```
score_1h >  +threshold  → 只允許做多
score_1h <  -threshold  → 只允許做空
中間                   → 不開新倉
```

`threshold` 初始猜測 ±0.1，**必須經回測校準**（見「回測校準」章節）。

### LTF 進出場（5m/15m 動能 delta）

```
方向=多 且 LTF delta 由負轉正  → 進場做多
方向=空 且 LTF delta 由正轉負  → 進場做空
LTF delta 反向轉折            → 出場（訊號出場）
或觸發停損/停利               → 出場
```

### 回測校準（前置里程碑，不可跳過）

高頻交易對成本極敏感，**不先回測就上 demo 等於盲跑**。

1. 抓取 BTC/SOL 的 5m/15m/1h 歷史資料（data_cache 分頁抓取）
2. 在回測引擎或獨立回測腳本中模擬此混合訊號（含手續費 0.05% + 滑價 0.05%）
3. 校準：HTF 閾值、LTF 進出場參數
4. 驗證：淨報酬為正、交易次數合理（避免過度交易）、MaxDD 可接受

## 執行與風險

### 執行（executor.py）

- `ccxt.okx` 開 **sandbox 模式**（demo 盤）
- 開倉前 `set_leverage(5)`，使用**逐倉（isolated margin）**
- 每資產最多 1 個持倉
- 所有下單帶冪等性處理，避免重複下單

### 風險引擎（risk.py）

| 規則 | 值 | 觸發行為 |
|------|-----|---------|
| 單日虧損上限 | -10% session 起始權益 | 強制平倉所有持倉，當日不再開新倉 |
| 單筆停損 | -2.5%（市價單） | 立即平倉 |
| 倉位大小 | 20% 權益作為保證金 × 5x | 單筆名義價值 ≈ 100% 權益 |
| 最大持倉 | 每資產 1 個 | 不疊倉 |
| 斷電/斷線 | 重啟後先跟 OKX 對帳 | 以交易所實際倉位為準 |

### 主迴圈（loop.py）

```
啟動 → 載入狀態 → 跟 OKX 對帳
   └─ 每 15-30 秒：
        抓 1h + 5m K線 → 算 HTF 方向 + LTF 訊號
        → 檢查風險限制（單日虧損、停損、持倉數）
        → 有訊號且無倉 → 設槓桿 + 開倉
        → 觸發出場 → 平倉
        → 更新 session 損益 + 存狀態
關閉（Ctrl+C）→ **保留持倉**並存狀態（下次啟動先對帳再繼續；與交易所一致即恢復）
```

### 狀態持久化（state.py）

- `bot/state.json`：持倉、進場價、當前損益、session 起始權益、單日虧損累計、啟動時間
- 崩潰重啟：先向 OKX 查實際倉位對帳，若檔案狀態與交易所不符，以交易所為準

## 錯誤處理與安全

- API 錯誤：指數退避重試；連續失敗超過 N 次 → 停止開新倉並告警
- 斷線恢復：重新連線後先對帳再繼續
- 冪等下單：同一個訊號/價格不會重複下單
- 日誌：`bot/bot.log` 記錄每次決策（訊號、風險檢查、下單、平倉）

## 測試

1. **單元測試**（pytest，放 `tests/test_bot_*.py`）
   - signals：HTF 閘門、LTF 進場/出場邏輯
   - risk：單日虧損觸發、停損計算、倉位大小
   - state：JSON 往返、崩潰恢復對帳
2. **回測校準**：歷史資料驗證混合訊號參數
3. **demo 連線測試**：用使用者的 OKX API key 跑連線 + 下單/平倉（僅 demo 盤）
4. **dry-run 模式**：只算訊號不下單，跑幾小時確認訊號頻率與行為合理

## 里程碑

1. **M1 回測校準**：抓取歷史資料、校準混合訊號參數、確認淨報酬為正
2. **M2 核心模組**：signals / risk / state 實作 + 單元測試
3. **M3 執行層**：executor（OKX demo）+ 連線測試
4. **M4 主迴圈**：loop + run_bot，dry-run 驗證
5. **M5 上線 demo**：使用者啟動運行，監控一段時間

## 非目標（YAGNI）

- 不接真錢交易（本階段）
- 不做自動停利/移動停損以外的複雜出場策略（先簡化）
- 不做 Web UI（本地 CLI 即可）
- 不整合進 Render/FastAPI
